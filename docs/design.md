# Дизайн эксперимента: масштабируемость D-Galois

## Цель

Измерить, как меняется время решения графовых задач при увеличении числа MPI-процессов **N** на одной машине, и оценить
параллельное ускорение (speedup) и эффективность.

- **N** — число MPI-процессов.
- **t** — число рабочих потоков на один процесс.
- **Алгоритм** — конкретное приложение D-Galois (например, `bfs-push-dist`).
- **runs** — сколько раз приложение прогоняет алгоритм внутри одного запуска (опция `--runs` Galois).
- **запуск (run)** — один вызов `mpirun ...` = `runs` повторений алгоритма с одной и той же параметризацией.

## Аппаратные ограничения

Из [`environment.md`](environment.md):

- 12 логических ядер
- 7.6 GiB RAM

## Варьируемые параметры

### 1. Число MPI-процессов

**N ∈ {1, 2, 4, 8}**

Обоснование:

- **N=1** — обязательный baseline для расчёта speedup.
- **N=2, 4** — типичные степени двойки, ожидается близкое к идеальному масштабирование.
- **N=8** — при `nproc=12` ещё помещается без oversubscribe (`8 × t=1 ≤ 12`); ожидаем заметные накладные расходы
  коммуникации.
- **N=16 не используется** — потребовало бы oversubscribe (12 ядер), что внесёт шум переключения контекста и исказит
  измерение чистого эффекта параллелизма.

### 2. Алгоритмы

| Алгоритм                   | Бинарник                 | Вход                                     |
|----------------------------|--------------------------|------------------------------------------|
| **BFS (push)**             | `bfs-push-dist`          | `lj.gr` + `lj.tgr`                       |
| **SSSP (push)**            | `sssp-push-dist`         | `lj.gr` + `lj.tgr`                       |
| **PR (pull)**              | `pagerank-pull-dist`     | `lj.gr` + `lj.tgr`                       |
| **TC** (Triangle Counting) | `triangle-counting-dist` | `lj-tc.sgr` (отдельный граф — com-Orkut) |

## Фиксированные параметры

| Параметр                              | Значение                         | Обоснование                                                                |
|---------------------------------------|----------------------------------|----------------------------------------------------------------------------|
| Граф (BFS/SSSP/PR)                    | LiveJournal (`lj.gr` / `lj.tgr`) | основной датасет                                                           |
| Граф (TC)                             | com-Orkut (`lj-tc.sgr`)          | неориентированный, очищен от self/multi (требование D-Galois TC)           |
| Потоков на процесс `-t`               | `max(1, ⌊nproc / N⌋ − 1)`        | минус один на коммуникационный поток; не превышаем 12                      |
| Партиционирование `--partition=`      | `oec` (Outgoing Edge-Cut)        | рекомендация Galois README для ≤ 16 хостов                                 |
| Тип связи `--exec=`                   | `Sync`                           | bulk-synchronous parallel — детерминирован(TC игнорирует флаг)             |
| Повторов `--runs`                     | 3                                |                                                                            |
| `GALOIS_DO_NOT_BIND_THREADS`          | `1`                              | обязательно при нескольких процессах на одной машине (документация Galois) |
| Стартовый узел BFS/SSSP `--startNode` | 0                                | фиксируем, чтобы исключить эту переменную                                  |

## Метрики

Galois записывает статистику в CSV по флагу `--statFile`. Для каждой пары (алгоритм, N) считаем:

| Метрика             | Формула                           | Смысл                                                      |
|---------------------|-----------------------------------|------------------------------------------------------------|
| **T(N)**            | медиана `Time` по `runs` запускам | время вычислительной фазы алгоритма                        |
| **Speedup S(N)**    | `T(1) / T(N)`                     | во сколько раз быстрее N узлов решают задачу               |
| **Efficiency E(N)** | `S(N) / N`                        | насколько эффективно используется параллелизм; 1.0 = идеал |
